## Lambda emission

12 cases from `t/03_lambda/lambda-tests.lisp`. Value tests use `int x = 5; int y = 7;`.

### no-params-with-return

A parameterless lambda with a return type keeps its empty parameter list. Omitting the `()` is invalid C++.

```lisp
(lambda () (declare (values int)) (return 42))
```

```cpp
[&]() -> int { return 42; }
```

Called as `f()` it evaluates to `42`.

### no-params-no-return

Without a return type the parameter list is still emitted; the type is deduced from `return`.

```lisp
(lambda () (return 42))
```

```cpp
[&]() { return 42; }
```

Called as `f()` it evaluates to `42`.

### explicit-capture-with-return

An explicit by-copy capture appears in the first bracket pair.

```lisp
(lambda ()
  (declare (capture x)
           (values int))
  (return x))
```

```cpp
[x]() -> int { return x; }
```

Called as `f()` it evaluates to `5`.

### default-capture-sees-outer-x

With no capture declaration the lambda defaults to `[&]` and sees outer variables.

```lisp
(lambda (a)
  (declare (type int a)
           (values int))
  (return (+ a x)))
```

```cpp
[&](int a) -> int { return (a)+(x); }
```

Called as `f(37)` it evaluates to `42`.

### two-params-no-return

Typed parameters render as a C++ parameter list; no `->` without `values`.

```lisp

  (declare (type int a)
           (type int b))
  (return (+ a b)))
```


Called as `f(40, 2)` it evaluates to `42`.

### by-value-default

### capture-default-moves-first

A capture-default must come first in C++; the generator reorders `(capture x =)` to `[=,x]`.

```lisp
(lambda ()
  (declare (capture x =)
           (values int))
  (return (+ x 1)))
```

```cpp
[=,x]() -> int { return (x)+(1); }
```

Called as `f()` it evaluates to `6`.

### mixed-captures-with-params

Explicit by-copy and by-reference captures mix freely alongside parameters.

```lisp

  (declare (capture x &y)

           (type int b)
           (values int))

```

```cpp

```

Called as `f(1, 2)` it evaluates to `15`.

### untyped-param-is-auto

Parameters without a declared type become `auto` (a C++14 generic lambda).

```lisp
(lambda (q) (return q))
```

```cpp
[&](auto q) { return q; }
```

Called as `f(9)` it evaluates to `9`.

### multi-form-body

Bodies hold multiple forms; earlier forms emit as statements before `return`.

```lisp
(lambda ()
  (declare (values int))
  (let ((y 2))
    (return (+ y 40))))
```

```cpp
[&]() -> int { auto y = 2; return (y)+(40); }
```

Called as `f()` it evaluates to `42`.

### immediate-call

A lambda in head position is parenthesised and can be invoked immediately.

```lisp
((lambda (a)
   (declare (type int a)
            (values int))
   (return a))
 41)
```

```cpp
([&](int a) -> int { return a; })(41)
```

The complete expression evaluates to `41`.

## Lambda errors

### multiple-values-error

More than one `values` type is rejected, mirroring `defun`.

```lisp
(lambda () (declare (values int float)) (return 1))
```

Signals an error containing `multiple return values unsupported`.
